## Browser end-to-end setup

Used the built production frontend in the Codex browser, served at `http://127.0.0.1:3107`, and a temporary synthetic backend at `http://127.0.0.1:5001`. Existing development servers were left untouched. The development page's HMR WebSocket repeatedly disconnected/reloaded through the browser environment, so actual interaction tests used the stable production build.

The fixture dispatched rating, like, rotation, album rename, person label, and source-reconciliation requests through the real Flask route handlers. Photo/album/person persistence and authentication identity were replaced with isolated in-memory synthetic records; publication, jobs responses, and index downloads were controlled by the fixture. This verifies the browser → HTTP → route → source/reconciliation → rendered-state path while allowing the published index to remain deliberately stale. It does not exercise Azure storage, real worker rebuilds/leases, or managed Web PubSub delivery.

No real account, library, photos, credentials, or Azure resources were changed. All fixture rows were synthetic. The local fixture used the explicit `__default__` test library. The backend's initial unconfigured-storage warning was expected; no real storage client was used for mutations.

## Remaining existing defects

### [P1, pre-existing] Invalidated downloads can overwrite the persistent index

Location: `frontend/src/services/localSortIndex.ts:260–264`; equivalent unconditional persistence remains in People and Albums.

The retained invalidation/IndexedDB reproduction still fails: rating 5 remains in the current memory cache, but an older download finishes last and overwrites the persistent snapshot under the same dirty/clean validator. Reload returns **1**, expected **5**. This race was previously established to exist in HEAD and is not counted as a newly introduced regression. The browser happy-path reload does not eliminate this concurrent-download failure.

### [P2, pre-existing] Two failed album renames restore an optimistic predecessor

Location: `frontend/src/mockups/prototype/store.tsx:1774–1777`.

Original → First → Second with both saves failing still leaves **First**, expected **Original**. The original rotation and person rollback fixes now pass, but the album callback still captures a potentially optimistic `previous` name. This existing defect remains unchanged.
